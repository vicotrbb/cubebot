# Bounded terminal

Terminal execution is disabled by default. `terminal_enabled: true` in the explicit controller configuration selects the runtime/tool layout and grants new turns a terminal budget. Do not enable it on an installation until its isolation, network and ownership checks have passed. Existing text-only authorities retain a zero terminal budget.

The native provider adapter carries stateless function calls. The agent owns the terminal schema, argument validation, model loop and invocation dispatch. Each issued execution authority permits at most eight commands and nine model requests inside its existing 60-second window. A human retry creates a new authority; uncertain terminal effects block that retry. Each command requests 1–30 seconds and retains at most 8,192 UTF-8 output bytes. All commands serialize across the agent workspace. Background descendants are stopped when the foreground command exits; persistent background services are outside this feature.

The runtime records central invocation intent before dispatch. The separate Rust supervisor records intent and outcomes in its own private persistent journal. Runtime intent/outcome custody and typed reconciliation continue through the existing authenticated control interface. Immutable invocation IDs bind the command, turn authority and duration. A repeated ID with different content is rejected. Crash recovery uses a distinct read-only lookup, never an execution retry. Intent without a proven outcome remains uncertain. Automatic turn retry is blocked while terminal effects remain uncertain. Chat retains command progress, outcomes and a Stop action.

The supervisor is PID 1 in the tool container. It runs as UID 0 with only KILL, SETUID and SETGID, no privilege escalation and a read-only root filesystem. It rejects other capability sets. Commands run through managed Bash with profiles disabled as UID 10002, after clearing supplementary groups, inheritable/ambient capabilities and inherited environment. Commands cannot read the supervisor's private journal or inspect its root-owned process. The runtime remains UID 10001 in a separate process namespace with its own mounts and credentials. A root-owned Unix socket authenticates runtime callers by kernel peer credentials without waiting for a workspace lock. At most eight authenticated requests may wait; commands remain serialized. A shared-Pod monotonic clock deadline prevents an expired queued request from starting. The runtime verifies the supervisor's UID.

Cancellation kills the tool PID namespace's other processes, including detached sessions, and reaps descendants before admitting another command. A lost caller connection or finite lease expiry requests cancellation. Permission/provider changes are checked during execution. Cancellation cannot undo filesystem or external effects. Unknown effects remain visible and are not treated as rollback. Old outcomes remain evidence; terminal final replies require a current execution epoch, provider revision and unexpired authority.

The existing UID-aware kernel filter permits public TCP/UDP and explicitly configured DNS, denies ungranted private/special-use and installation infrastructure destinations, and preserves runtime-only network paths. The trusted NET_ADMIN initializer must finish before either application container starts. Tools cannot modify the policy. Installation topology must include infrastructure using public addresses. This feature does not add private network grants.

Workspace, runtime journal and supervisor journal use distinct PVC subdirectories. Keep `fsGroupChangePolicy: OnRootMismatch`; recursive ownership changes can make private journals fail closed on remount. ReadWriteOncePod and the existing conservative physical-attempt reconciliation prevent speculative replacement. A missing Pod or quiescence report alone does not prove execution stopped. A proven runtime exit allows a guarded stop of the remaining tool container without an impossible acknowledgement; replacement still waits for full termination evidence.

The hard process limit is 128 per real UID, shared across agents on a node. This deliberately bounds the first terminal mode's process creation; higher concurrent capacity needs qualified per-Pod cgroup PID limits. Supervisor evidence uses the existing 16 MiB / 4,096-record journal bounds and stops admission when full. It retains evidence rather than silently recycling invocation identities. Browser automation, MCP, delegation and memory remain outside this feature.

Run `just check`, `just integration` and `just smoke` before qualification. `just cluster-terminal` owns a disposable dual-stack Kubernetes/CSI fixture for hostile commands, output/duration bounds, cancellation, credential separation and retained workspace behavior. Supply `CUBEBOT_QUALIFICATION_DIRECTORY` outside the checkout. Generated evidence is never source material to commit.

For the shipped runtime/control/tool path with a live provider, supply `OPENAI_API_KEY_FILE` and the external qualification directory, then run `CUBEBOT_QUALIFY_TERMINAL=1 just cluster-chat`. This uses only owned disposable infrastructure and cleans it up on completion or failure. Its API submission is not website acceptance. Add `CUBEBOT_TERMINAL_MANUAL=1` to wait for a person to submit the initial script/failure/fix/verification request through the real website. Private temporary login instructions are written into the external evidence directory. The manual wait is bounded to ten minutes. No browser automation is used by the terminal workflow.

A passing mechanism probe, build or API submission cannot establish website acceptance, all supported cluster profiles, hostile-code isolation on another runtime, or production scale. Report the actual tested configuration and any blocked checks separately.
