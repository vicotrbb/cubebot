# Terminal execution

Terminal execution is disabled by default. `terminal_enabled: true` in the explicit controller configuration selects the runtime/tool layout and grants new turns terminal eligibility. Do not enable it on an installation until its isolation, network and ownership checks have passed. Existing text-only authorities remain ineligible for tools.

The native provider adapter carries stateless function calls. The agent owns the terminal schema, argument validation, model loop and invocation dispatch. There is no command-count, turn-duration, command-duration or output-capture budget. Work continues while it is authorized. Commands serialize across the agent workspace. Admission is fenced before intent is written and reopened only after the process tree is stopped and its outcome is durable. An error cannot release a queued writer during supervisor shutdown. Background descendants are stopped when the foreground command exits; persistent background services are outside this feature.

Each command writes its complete combined stdout/stderr to `.cubebot-terminal-output/<invocation-id>.log` in the persistent workspace. The result contains a tail preview and the full file path. This keeps transport, journals and model context small without stopping a command or discarding output when its output grows. The agent can inspect or analyze the full file with subsequent commands. These are mutable workspace files, subject to the same filesystem permissions and physical capacity as other workspace data.

Active turns and invocations renew short security leases after checking the current epoch, sender access and provider revision. The leases are not task deadlines: a healthy authorized command can run for hours. A disconnected runtime cannot renew itself indefinitely. Loss of authorization, cancellation or lease expiry stops the process tree. Runtime credentials renew during long work as well.

The runtime records central invocation intent before dispatch. The separate Rust supervisor records intent and outcomes in its own private persistent journal. Runtime intent/outcome custody and typed reconciliation continue through the existing authenticated control interface. Immutable invocation IDs bind the command and turn authority. A repeated ID with different content is rejected. Crash recovery uses a distinct read-only lookup, never an execution retry. Intent without a proven outcome remains uncertain. Automatic turn retry is blocked while terminal effects remain uncertain. Chat retains command progress, outcomes and a Stop action.

The supervisor is PID 1 in the tool container. It runs as UID 0 with only KILL, SETUID and SETGID, no privilege escalation and a read-only root filesystem. It rejects other capability sets. Commands run through managed Bash with profiles disabled as UID 10002, after clearing supplementary groups, inheritable/ambient capabilities and inherited environment. Commands cannot read the supervisor's private journal or inspect its root-owned process. The runtime remains UID 10001 in a separate process namespace with its own mounts and credentials. A root-owned Unix socket authenticates runtime callers by kernel peer credentials without waiting for a workspace lock. The socket admission queue remains bounded; commands remain serialized. Shared-Pod monotonic deadlines prevent an expired queued request or stale renewal from granting new execution. Renewal frames are cancellation-safe even when fragmented. The runtime verifies the supervisor's UID.

Cancellation kills the tool PID namespace's other processes, including detached sessions, and reaps descendants before admitting another command. Output inspection runs as the same unprivileged command user, so an output-file symlink cannot expose supervisor or runtime secrets. A lost caller connection or finite lease expiry requests cancellation. Permission/provider changes are checked during execution. Cancellation cannot undo filesystem or external effects. Unknown effects remain visible and are not treated as rollback. Old outcomes remain evidence; terminal final replies require a current execution epoch, provider revision and unexpired authority.

The existing UID-aware kernel filter permits public TCP/UDP and explicitly configured DNS, denies ungranted private/special-use and installation infrastructure destinations, and preserves runtime-only network paths. The trusted NET_ADMIN initializer must finish before either application container starts. Tools cannot modify the policy. Installation topology must include infrastructure using public addresses. This feature does not add private network grants.

Workspace, runtime journal and supervisor journal use distinct PVC subdirectories. Keep `fsGroupChangePolicy: OnRootMismatch`; recursive ownership changes can make private journals fail closed on remount. ReadWriteOncePod and the existing conservative physical-attempt reconciliation prevent speculative replacement. A missing Pod or quiescence report alone does not prove execution stopped. A proven runtime exit allows a guarded stop of the remaining tool container without an impossible acknowledgement; replacement still waits for full termination evidence.

The hard process limit is 128 per real UID, shared across agents on a node. This deliberately bounds the first terminal mode's process creation; higher concurrent capacity needs qualified per-Pod cgroup PID limits. Supervisor evidence uses the existing 16 MiB / 4,096-record journal bounds and stops admission when full. It retains evidence rather than silently recycling invocation identities. Browser automation, MCP, delegation and memory remain outside this feature.

Run `just check`, `just integration` and `just smoke` before qualification. `just cluster-terminal` owns a disposable dual-stack Kubernetes/CSI fixture for hostile commands, long execution with renewable authority and full output retention, cancellation, credential separation and retained workspace behavior. Supply `CUBEBOT_QUALIFICATION_DIRECTORY` outside the checkout. Generated evidence is never source material to commit. Both cluster runners can reuse an explicitly supplied caller-owned `CUBEBOT_QUALIFICATION_BUILDER`; that builder remains the caller's cleanup responsibility.

For the shipped runtime/control/tool path with a live provider, supply `OPENAI_API_KEY_FILE` and the external qualification directory, then run `CUBEBOT_QUALIFY_TERMINAL=1 just cluster-chat`. This uses only owned disposable infrastructure and cleans it up on completion or failure. Its API submission is not website acceptance. Add `CUBEBOT_TERMINAL_MANUAL=1` to wait for a person to submit the initial script/failure/fix/verification request through the real website. Private temporary login instructions are written into the external evidence directory. The manual wait is bounded to ten minutes. No browser automation is used by the terminal workflow.

A passing mechanism probe, build or API submission cannot establish website acceptance, all supported cluster profiles, hostile-code isolation on another runtime, or production scale. Report the actual tested configuration and any blocked checks separately.
