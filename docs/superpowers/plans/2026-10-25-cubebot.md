# Cubebot implementation plan

> Execute sequentially with superpowers:executing-plans. Keep this plan and the evidence ledger current. Finish a milestone's acceptance criteria before advancing.

**Goal:** Implement the accepted Cubebot application and prove its behavior through real workflows.

**Architecture:** Three apps, one modular Rust orchestrator, one Rust agent package with a second tool-runner binary, and a TanStack Start console. PostgreSQL owns structured state; agent state access goes through the orchestrator. Only protocol contracts and provider adapters are shared libraries.

**Tech stack:** Existing Rust/Tokio/Axum, PostgreSQL, TanStack Start/React/TypeScript/Bun/Vite. Select concrete persistence and Kubernetes clients with their first feature.

**Spec:** MANIFESTO.md, ARCHITECTURE.md, docs/design/software-specification.md, docs/design/shared-storage.md, docs/design/qualification.md, and all accepted docs/adr decisions.

## Global constraints

- Every authored function has cyclomatic complexity <=15. No first-party exclusions.
- Run `just check` and built-process `just smoke` for each completed milestone, plus its integration workflow.
- Retain durable state until authorized deletion. No direct database credentials in agents.
- Installation-managed connections default to all eligible agents; specific grants are optional.
- No deployment, release, external infrastructure mutation, or unapproved live-provider spending.
- Preserve source history, explicit permissions, revision checks, durable command identities, and uncertain-effect evidence.
- Mark incomplete behavior honestly. Mock/provider fixtures establish protocol behavior only.

## Review focus

- Lost acknowledgements must not duplicate accepted work; test replay and request-content conflicts.
- Revoked/suspended users and agents must lose new-operation access; test live revocation.
- Uncertain external effects must block blind replay and unsafe executor replacement; crash/partition tests.
- Concurrent correction, cancellation, completion and acceptance must reject stale revisions; race tests.
- Storage pressure and interrupted publication/restore must preserve retained evidence; fault tests.

## Task 1: Persistence and identity

**Dependencies:** existing scaffold. **Produces:** concrete PostgreSQL pool/migrations, authenticated human identity and effective access for later domain operations.

**Files:** apps/orchestrator/src/identity/{mod,accounts,sessions,access}.rs; apps/orchestrator/src/operations/database.rs; apps/orchestrator/src/api/{mod,identity}.rs; apps/orchestrator/migrations/*.sql; apps/orchestrator/tests/{persistence,identity}.rs; configuration, lockfiles and local database runner.

- [x] Add a real PostgreSQL integration runner using an isolated local database. Require explicit opt-in for database tests, never silently pass missing dependencies. Verify migrations apply twice and survive pool reconnection, constraints reject invalid/duplicate identity bindings, and rollback leaves no partial records.
- [x] Implement versioned SQLx migrations and bounded pool startup; fail invalid configured databases at startup. Keep liveness separate from database readiness.
- [x] Implement one-time administrator bootstrap, Argon2id built-in passwords, expiring opaque hashed sessions, logout and suspension. No open registration. Test concurrent bootstrap, invalid credentials, expiry, logout, and suspension against real HTTP/database boundaries.
- [x] Implement administrator-created accounts/invitations, local teams, explicit scoped capability grants, explainable access, and immediate new-operation revocation. Managers cannot escalate or infer private content rights. Test denied sibling resources and team removal.
- [x] Implement optional OIDC authorization-code/PKCE with issuer/audience/state/nonce validation, explicit subject binding and admission rules. No email linking or suspension bypass. Qualify with a controlled issuer; mark live issuer evidence separately.
- [x] Complete the minimal persisted agent create/read/list resource from Task 2 to verify actual scoped disclosure. This is an acceptance dependency, not Kubernetes/runtime qualification.
- [x] Acceptance: authenticated administrator provisions a member, grants/revokes team access, member logs in and sees only authorized resources, restart retains identity and session rules. `just check`, `just smoke`, real PostgreSQL identity integration pass.

Milestone 1 backend acceptance completed on 2026-10-26; see the evidence ledger. Web/PWA, actual content domains, external issuer compatibility and production qualification remain in their later milestones.

## Task 2: Agent lifecycle and Kubernetes operations

**Files:** apps/orchestrator/src/agents/{mod,definitions,lifecycle,kubernetes}.rs; protocol runtime contracts; migrations; tests/lifecycle and tests/system lifecycle workflows; deploy local fixtures.

Create/read/list are implemented and verified as the identity acceptance dependency. Continue with updates, lifecycle transitions and retirement; do not interpret persisted sleeping intent as a Kubernetes observation.

- [ ] Test then implement create/update/list/retire with stable typed identity, managers, revision conflicts, idempotent request digest and transactional audit/outbox. Default sleep; retain data on retirement.
- [ ] Implement scoped Kubernetes client and pod/PVC reconciliation from database intent; separate trusted runtime/tool containers and retained workspace mounts. Verify ownership UIDs, reject ambiguous adoption, record blocked provisioning and drift.
- [ ] Qualify credential isolation, public/private egress and exclusive execution fencing in a disposable local cluster before enabling arbitrary tools. Hold replacement when prior executor termination cannot be proved. Record any ADR conflict as an essential decision.
- [ ] Acceptance: create during API outage, recover lost create response, wake/sleep/restart/retire without losing identity/workspace; database outage causes no destructive cleanup. Local controlled-cluster tests plus G1–G3 evidence and standard gates pass. No external cluster mutation.

Controlled provider tests pass; each advertised live adapter requires separate credential-backed evidence. Subscription paths remain unqualified until independently proven.
