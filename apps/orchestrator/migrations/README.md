# Database migrations

The orchestrator embeds and applies SQLx migrations from this directory when a database is configured. `0001_identity.sql` creates the singleton installation bootstrap record, built-in accounts, hashed sessions and identity audit trail. The build script tracks migration changes. `0002_invitations.sql` adds login-bound expiring invitations with digested bearer tokens and redemption/revocation provenance. `0003_teams_access.sql` adds local teams, scoped grants, durable non-secret command receipts and their transactional event journal. `0004_identity_request_replay.sql` adds separate one-way password proofs for secret-bearing command replay and invitation revisions/redemption identities. `0005_authentication_limits.sql` adds persisted bounded password-verification windows on human accounts. Applied migrations are immutable; add a new numbered migration for changes.

`just integration` applies migrations against real isolated PostgreSQL, reconnects, reapplies them and verifies constraints and transaction rollback. Agents never receive database credentials or access the schema directly.

Backup and restore follow [Cubebot-coordinated backup and restore workflows](../../../docs/adr/packaging.md#cubebot-coordinated-backup-and-restore-workflows) and [Backups without pauses](../../../docs/adr/packaging.md#backups-without-pauses); a restore loads a `pg_dump` taken at any migration up to this release's, then migrates forward. Coordinated maintenance upgrades ([Coordinated maintenance upgrades](../../../docs/adr/packaging.md#coordinated-maintenance-upgrades)) remain unimplemented. Development migration tests do not qualify those workflows.
