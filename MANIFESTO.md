# Cubebot manifesto

We are building Cubebot so individuals and organizations can run persistent AI agents on infrastructure they control. Install it on Kubernetes, create agents, give them tools and responsibilities, and work alongside them through a shared web console and mobile PWA.

Cubebot brings conversational agents, personal workspaces, and collaboration into a runtime built for Kubernetes. Its ambition spans a personal assistant, a team of specialists, and thousands of agents working across an organization.

An agent has a lasting identity. It owns its configuration, memories, conversation history, and workspace. While running, it has a dedicated pod with allocated resources, persistent storage, and access to a terminal, browser, and authorized integrations. Its identity and durable state survive restarts, upgrades, and replacement of its execution environment. Agents sleep when idle by default and wake for work or scheduled memory maintenance. Managers can keep selected agents running.

Rooms are shared places where people and agents communicate and coordinate work. Direct mentions address agents; a tool-free LLM coordinator routes unaddressed requests. Agents can exchange direct messages, delegate tasks, report results, and participate in multiple rooms. Teams and swarms build on these same capabilities, with explicit ownership, participation rules, and limits that keep collaboration useful as it grows.

The orchestrator keeps the system coherent. It handles APIs, mailboxes, rooms, scheduling, permissions, and Kubernetes lifecycle operations. Work and messages remain durable across interruptions. Recovery accounts for actions already taken, and uncertain outcomes stay visible. People can inspect progress, intervene, cancel work, and understand failures.

Agents should accumulate knowledge throughout their lives. Each agent has one unified memory, used across all its conversations, rooms, and tasks. Cubebot's ambition of "infinite memory" means preserving useful knowledge beyond any single model context window. During work, agents retrieve relevant information and maintain compact working context. During idle periods, they "dream": consolidate memories, reconcile contradictions, summarize history, and improve retrieval. People can see when an agent is dreaming and inspect the resulting memory changes. Consolidation preserves source history and provenance; source deletion follows explicit retention or deletion rules. Recall and continuity must be tested rather than assumed.

Autonomy comes with explicit boundaries. People decide which tools, credentials, data, and rooms an agent may access and how much time, compute, and money it may spend. Agents act autonomously within those grants, without approval for each invocation. Installation administrators can inspect all agent content. Access controls govern what other users can inspect directly, while an agent may reuse its knowledge wherever it participates. Important actions and decisions leave an inspectable record.

Cubebot owns its agent engine and supports different models and providers through adapters with explicit capabilities. API credentials, local models, and supported subscription integrations should fit without binding the project to one vendor. Core tools are native to Cubebot, with MCP as the default extension path for external integrations. Tools and connectors extend what agents can do while preserving the same permission and accountability model.

Skills are a core part of the ecosystem: reusable procedures with instructions, references, and optional scripts. People can create and import skills, agents can develop their own, and idle dreaming can turn lessons from past work into better procedures. Skills enter a shared installation library by default, with each agent selecting what to install. Skills have inspectable revisions and load when needed. Dream reports show skill changes alongside memory changes, and using a skill preserves the agent's existing permissions.

The core runtime and orchestration services are built in Rust. A dedicated TanStack Start frontend, using Bun and Vite, serves the web console and installable PWA. It gives people one place to create agents, manage access, chat, organize rooms, inspect memories and skills, and follow work across desktop and mobile. Exceptional responsiveness, visual quality, and accessibility are product requirements, measured through real workflows. Deployment and daily operation should remain approachable for a single person as the platform grows to support larger organizations.

We will judge Cubebot by whether agents can carry useful work forward over time, collaborate without losing responsibility, recover without losing their history, and remain understandable and controllable by the people who rely on them.
